# Repository documentation rollout

The user has 14 repositories. The migration is incremental so existing code,
license terms, README evidence and confidential details can be reviewed for
each project. Every change is proposed on a separate branch and Pull Request.

## Shared standard

All project covers use the same charcoal and champagne visual system.
Each repository README has a short first screen, links to the actual source
and validation instructions, and optional deeper technical sections.

A profile landing page and a learning archive are exceptions in length and
information architecture, not in visual tone.

## Review rules

1. Never make a private repository public.
2. Never publish company infrastructure, credentials, customer data or
   proprietary project details.
3. Preserve working historical material while improving organization.
4. Do not promise that code executes when the relevant tests could not run.
5. Merge only after review, using existing repository default branches.
